# SSO API Reference

## Organization Portal API

The event subdomain communicates with the organization portal to validate SSO tokens.

### Validate SSO Token

Validates a one-time SSO token and returns user information.

**Endpoint**: `POST /api/validate-sso-token`

**Base URL**: Configured via `ORG_PORTAL_URL` environment variable
- Production: `https://app.glimzo.ai`
- Local: `http://127.0.0.1:8000`

**Request Headers**:
```
Content-Type: application/json
```

**Request Body**:
```json
{
  "token": "2Y3kHMivTKtMQAteGLEnvb2zFwLOgMC6UtoLTj5W4VM1e8YZK0ieTCAOnLppvjAw"
}
```

**Success Response** (200 OK):
```json
{
  "success": true,
  "user": {
    "user_id": 123,
    "organization_id": 5,
    "event_id": 18,
    "email": "admin@example.com",
    "name": "John Doe"
  }
}
```

**Error Responses**:

**400 Bad Request** - Missing token parameter:
```json
{
  "error": "Token required"
}
```

**401 Unauthorized** - Invalid or expired token:
```json
{
  "error": "Invalid or expired token"
}
```

**500 Internal Server Error** - Server error:
```json
{
  "error": "Internal server error"
}
```

## Token Lifecycle

1. **Generation**: Token is generated by organization portal when user clicks "Login as"
2. **Storage**: Token is stored in cache with 5-minute expiry
3. **Usage**: Token is sent to event subdomain via URL parameter
4. **Validation**: Event subdomain validates token with organization portal
5. **Deletion**: Token is immediately deleted after successful validation (one-time use)
6. **Expiry**: Unused tokens automatically expire after 5 minutes

## Security Considerations

### Token Format
- Tokens are random 64-character strings
- Generated using cryptographically secure random bytes
- URL-safe encoding

### Token Storage
- Stored in cache (Redis/Database) on organization portal
- Associated with user and event information
- Automatically cleaned up on expiry

### Validation Rules
1. Token must exist in cache
2. Token must not be expired (5 minutes)
3. Token must be associated with valid user
4. User must have access to the requested event
5. User must belong to the correct organization

### Network Security
- All production communication uses HTTPS
- Timeout set to 10 seconds to prevent hanging
- Failed attempts are logged for security monitoring

## Implementation Details

### Event Subdomain Code

```php
// Validate token with organization portal
$response = Http::timeout(10)->post($orgPortalUrl . '/api/validate-sso-token', [
    'token' => $token
]);

if ($response->successful()) {
    $data = $response->json();
    
    if ($data['success'] ?? false) {
        $userData = $data['user'];
        
        // Verify event and organization
        if ($userData['event_id'] == config('event.event_id') &&
            $userData['organization_id'] == config('event.org_id')) {
            
            // Create/update admin user
            $admin = Admin::updateOrCreate(
                ['email' => $userData['email']],
                [
                    'name' => $userData['name'],
                    'organization_id' => $userData['organization_id'],
                    'event_id' => $userData['event_id'],
                    'last_login_at' => now(),
                ]
            );
            
            // Create session
            session([
                'admin_logged_in' => true,
                'admin_id' => $admin->id,
                'admin_email' => $admin->email,
                'admin_name' => $admin->name,
                'sso_login' => true,
            ]);
            
            return redirect()->route('admin.dashboard');
        }
    }
}
```

## Error Handling

The event subdomain handles various error scenarios:

### Network Errors
- Connection timeout (10 seconds)
- DNS resolution failure
- SSL certificate errors

**User Message**: "Authentication service unavailable. Please try again later or use regular login."

### API Errors
- 400 Bad Request
- 401 Unauthorized
- 500 Internal Server Error

**User Message**: "Invalid or expired login link. Please try again."

### Validation Errors
- Event ID mismatch
- Organization ID mismatch

**User Message**: "Access denied: You do not have permission to access this event."

## Monitoring and Logging

### Successful Login

### Failed Validation

## Troubleshooting

### Issue: API returns 404
**Cause**: Organization portal doesn't have the API endpoint
**Solution**: Ensure organization portal is updated with SSO API

### Issue: Token always invalid
**Cause**: Token might be expired or already used
**Solution**: Generate a new token and try immediately

### Issue: Event ID mismatch
**Cause**: Token was generated for different event
**Solution**: Verify EVENT_ID in .env matches the token's event

### Issue: Connection timeout
**Cause**: Organization portal is unreachable
**Solution**: Check ORG_PORTAL_URL and network connectivity
